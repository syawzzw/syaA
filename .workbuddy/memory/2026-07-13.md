## 离线爬取图片路径 Bug 修复
- **问题**：离线网页中图片标签显示 `src="none.gif" R2706xxx.png"` 而非正确的本地路径
- **根因**：`re.sub` 使用 `\1`/`\2` 反向引用语法，当 replacement 字符串（local_name）以数字开头时，正则引擎将开头的数字误解为反向引用（如 `\122` = 第122个捕获组），导致字符被错误吞噬
- **影响范围**：所有图片文件名以数字开头的帖子（如 Discuz 论坛的 `zoomfile` 图片 URL）
- **修复方案**：
  - L2870-2874: 图片 src/zoomfile/file 替换：`\1` + local_name + `\2` → `\g<1>` + local_name + `\g<2>`
  - L2891-2896: CSS/JS href/src 替换：同上
- **验证**：测试脚本确认修复前后对比，修复后输出正确
- **遗留**：已保存的离线网页需要重新爬取才能修复（或写批量修复脚本扫描并重写 HTML）

## 普通爬取 crawled.json 未生成问题
- **现象**：用户进行普通爬取后 output/crawled.json 不存在
- **原因**：`_crawl_worker()` 函数缺少顶层异常保护，当进程被强制终止（关闭窗口/kill）时，L1529 的 `_save_crawled_json()` 来不及执行；且无 `try/finally` 保证退出时保存
  - 日志显示 18:24:32 启动爬取(2000000-3000000, 100万帖)，19:01:58 最后一条日志，无结束统计行
  - 已处理约 39223 条但 crawled.json 没写入
- **修复方案**（L1454-1567）：
  1. `crawled` 变量提前到函数开头初始化为 `{}`（确保 finally 能访问）
  2. L1490 起：线程分配+join+保存+统计 全部包入 `try` 块
  3. L1557-1560: 新增 `except` 分支，捕获未处理异常并输出完整 traceback 到日志
  4. L1561-1567: 新增 `finally` 块 —— 无论正常结束/用户中断/异常退出/关闭窗口，都执行 `_save_crawled_json()` 并调用 `_crawl_done()`
